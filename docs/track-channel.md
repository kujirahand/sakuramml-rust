# トラック番号とMIDIチャンネル番号の仕様

この文書では、サクラMML、内部データ、Standard MIDI File（SMF）、MIDIダンプの間で、トラック番号とチャンネル番号をどのように対応させるかを定めます。

## 結論

| 対象 | 表記範囲 | 内部表現 | 変換 |
|---|---:|---:|---|
| サクラMMLの `TR(n)` | 0～999 | 0始まり | `n` をそのまま使う |
| SMFの `MTrk` | 番号フィールドなし | ファイル内の出現順を0始まりで数える | 先頭のチャンクがトラック0 |
| MIDIダンプの `TR(n)` | 0始まり | SMFのチャンク順 | チャンク番号をそのまま出力する |
| サクラMMLの `CH(n)` | 1～16 | 0～15 | 読み込み時に `n - 1` |
| MIDIイベントのチャンネル | 0～15 | ステータスバイトの下位4ビット | ダンプ時に `+ 1` して `CH(n)` とする |

`TR` と `CH` では番号の基準が異なります。`TR` は0始まり、`CH` は1始まりです。

## `TR(n)` の仕様

`TR(n)`、`TRACK(n)`、`Track(n)` は、カレントトラックを0始まりのトラック `n` に切り替えます。トラック0も通常のトラックとして使用できます。

コンパイラは起動時にトラック0を1つ作成します。まだ存在しない番号を指定した場合は、指定番号までトラックを追加します。そのため、たとえば最初に `TR(2)` を指定すると、SMFにはトラック0、1、2の3つの `MTrk` チャンクが出力されます。

```text
TR(0)  // 内部トラック0、SMFの先頭MTrk
TR(1)  // 内部トラック1、SMFの2番目のMTrk
TR(2)  // 内部トラック2、SMFの3番目のMTrk
```

計算式で `TR`、`TRACK`、`Track` を参照した場合も、現在の0始まりのトラック番号を返します。

### 字句解析テストの `[Track,0]` について

`tokens_to_str()` が `TR(1)` を `[Track,0]` と表示しても、引数が0へ変換されたことを意味しません。この表示の `0` はシステム関数定義の `tag1` から設定された `Token.value_i` です。実際の引数 `1` は子トークンに保持され、実行時に評価されます。

実行時の処理は、評価した引数をそのまま `Song::change_cur_track()` に渡します。したがって、`TR(1)` が選択するのは内部トラック1です。

## `CH(n)` の仕様

`CH(n)`、`CHANNEL(n)`、`Channel(n)` は、カレントトラックでこれ以降に生成するMIDIイベントのチャンネルを1～16で指定します。

MIDIステータスバイトではチャンネルが0～15で表されるため、コンパイラは `CH(n)` を内部値 `n - 1` に変換します。MIDIダンプでは逆に、ステータスバイトの下位4ビットへ1を加え、`CH(1)`～`CH(16)` として出力します。

```text
CH(1)   // MIDIステータスバイトのチャンネル値0
CH(10)  // MIDIステータスバイトのチャンネル値9
CH(16)  // MIDIステータスバイトのチャンネル値15
```

計算式で `CH`、`CHANNEL` を参照した場合は、1始まりの現在値を返します。

トラックを順番に作成した場合、トラック番号1～16の初期チャンネルは同じ番号になります。トラック0の初期チャンネルは1です。

現行実装では、存在しない複数のトラックを飛び越して `TR(n)` を指定すると、追加される中間トラックにも指定先トラックと同じ初期チャンネルが設定されます。これは公開仕様として依存すべき動作ではありません。チャンネルを確実に指定する必要があるデータでは、トラックの初期値に依存せず `CH(n)` を明記してください。

## MIDIダンプの `TR(n)`

SMFの `MTrk` チャンク自体にはトラック番号が保存されていません。MIDIダンプでは、ファイル内のチャンクの出現順を0始まりで数え、その番号を変更せず `TR(n)` として出力します。

ダンプ時にチャンク番号へ1を加えてはいけません。`+ 1` すると、ダンプ結果を再コンパイルしたときに未指定のトラック0が先頭へ追加され、すべてのトラックが1つ後ろへずれます。

たとえば、3つの `MTrk` チャンクを持つSMFは次のように出力します。

```text
TR(0)
TR(1) CH(1)
TR(2) CH(10)
```

先頭チャンクがメタイベントだけ、または空であっても、後続チャンクの番号を詰めません。SMF内の構造を保つため、常に実際のチャンク順を使用します。

## MIDIダンプの `CH(n)`

各トラックの先頭では、最初に見つかったチャンネルイベントのチャンネルを `CH(n)` として `TR(n)` と同じ行に出力します。対象はNoteOnやControl Changeだけではなく、NoteOff、Program Change、Pitch Bendなど、ステータスバイトが `0x80`～`0xEF` のすべてのチャンネルイベントです。

同じトラック内でイベントのチャンネルが変化した場合は、変化した最初のイベントの直前に新しい `CH(n)` を出力します。同じチャンネルが続く間は重複して出力しません。

チャンネルイベントを1つも持たないトラックでは、`CH(n)` を推測せず `TR(n)` だけを出力します。

## オリジナル実装との互換性

Pascal/Delphi版のオリジナル実装でも、トラック番号は0始まりです。

- `sakuramml/mml_system.pas` は初期化時に `SetCurTrack(0)` を呼ぶ
- `SetCurTrack(Index)` は `Index` を変更せず、曲情報とSMF出力の両方で同じトラック番号として使う
- `sakuramml/mml_types.pas` は `TrackNo := Index` とし、トラック0の内部チャンネルを0、それ以外の初期チャンネルを `(Index - 1) mod 16` とする

したがって、Rust版で `TR(1)` を内部トラック0へ変換するのは互換仕様ではありません。`TR(1)` はオリジナル実装でもRust版でもトラック1を選択します。

## 実装上の対応箇所

- `src/lexer/command.rs`: `TR`、`CH` の引数を子トークンとして読み取る
- `src/runner/structure.rs`: `TR` の引数をそのままトラック番号に使い、`CH` を0～15へ変換する
- `src/song.rs`: トラック0の作成と、指定番号までのトラック追加を行う
- `src/midi.rs`: 内部トラック順に `MTrk` を生成し、ダンプ時にチャンク順とチャンネルを出力する
- `src/runner/function.rs`: 計算式で参照する現在の `TR` と `CH` を返す
- `sakuramml/mml_system.pas`: オリジナル実装でトラック番号をそのまま選択する
- `sakuramml/mml_types.pas`: オリジナル実装のトラック番号と初期チャンネルを設定する

関連する利用方法は[トラック・チャンネル・タイムポインタ](syntax-track.md)も参照してください。
